# 유저스토리 키트 에이전트 지침

## 기준 자료와 우선순위

- 사용자 호칭은 토순님, 존댓말로 보고한다.
- 작업 전 현재 코드, 원본 템플릿, 원본 가이드를 확인한다.
- 시스템·개발자 지침을 우선 지킨다. 그 범위에서 [원본 제작 가이드](references/guidev0929.md)가 일반 제작 요청 및 이 요약보다 우선한다.
- 원본은 전달 파일 `04_TEMPLATES_GUIDE_v0929.md`다. 내부 제목과 10장의 파일명 예시는 v0824로 남아 있다. 전달본을 기준으로 하되 원문 표기를 고치거나 다른 v0824 파일로 대체하지 않는다.
- 제작 시 가이드를 끝까지 읽고 요청·템플릿과 대조한다. 충돌·모호한 부분은 관련 원문을 다시 확인한다. 큰 충돌, 모호한 의도, 부족한 필수 파일은 작업 전에 질문한다.
- 새 템플릿이 유일한 HTML 골격이다. 이전 저장소의 카드·저널·게임 페이지를 골격으로 바꿔 끼우지 않는다.

## 스킬 역할

- [00. 총괄](skills/00-userstory/SKILL.md): 입력 확인, 블록 절차 연결, 전체 조립, 직접 화면 검수·보고와 요청 시 별도 ZIP 포장. 전체 검수만 요청되면 읽기 전용이다.
- [01. 플레이북](skills/01-playbook/SKILL.md): 사용자 HTML 이관, 순수 영상/이미지 조립과 해당 블록의 조작만 맡는다. 플레이북 내부 형식을 고정하지 않는다.
- [02. 시나리오 캔버스](skills/02-scenariocanvas/SKILL.md): 카드/세로형 시캔과 해당 블록의 배치·전환만 맡는다.
- [03. 데이터북](skills/03-databook/SKILL.md): 선택 데이터북 조립 또는 부재 시 전체 블록 제거만 맡는다.
- 블록 스킬은 같은 출력 사본의 해당 슬롯만 작업한다. 다른 블록을 재생성하거나 단일 블록 검사로 전체 납품 합격을 선언하지 않는다. 공통 지침·가이드는 동일 작업에서 읽은 내용을 이어 사용한다.

## 골격과 부품의 역할

- `assets/template`는 전달용 HTML 골격, `assets/components`는 붙여넣기용 본문·CSS·JS다. 시캔 부품에는 플레이북·데이터북·헤더·main/section 골격을 넣지 않는다.
- 순수 미디어는 [제작 태스크](tasks/build.md)의 양식을 선택하고 `scripts/userstory.py build`로 조립한다. 이미지형 플레이북과 세로형 시캔은 공통 img 부품을 한 번만 공유한다.
- 작성된 플레이북 HTML은 [HTML 이관 태스크](tasks/playbookhtml.md)로 본문·CSS·JS·로컬 의존 리소스를 옮긴다. 원본의 게임·영상 분기·SVG 애니메이션과 각 블록의 PDF 등은 원본 기능을 유지하는 슬롯 조립으로 처리한다. 자동 조립기의 범위를 넘어서는 파일을 버리거나 영상·이미지 양식으로 평탄화하지 않는다.
- 제작 결과는 플러그인 밖 새 콘텐츠 폴더에 만든다. ZIP은 요청 시 [별도 포장 태스크](tasks/package.md)에서 만든다. 원본이나 기존 납품본을 묵시적으로 덮어쓰지 않는다. 개발 PC의 유저스토리 폴더는 제작 시 필요한 런타임 의존성이 아니다.

## 템플릿과 패키지

- [assets/template](assets/template/index.html)의 원본 파일·붙여넣기 표시를 보존한다. 제작은 별도 출력 사본에서 한다. Git은 빈 폴더를 추적하지 않으므로 사본 생성 시 표준 리소스 폴더를 복원한다.
- HTML은 각 붙여넣기 표시 사이만 작성한다. 예외는 출력 사본의 `<head><title>` 텍스트와 최상위 `data-screen-name`의 타이틀 치환, 데이터북 부재 시 ✂ 표시를 포함한 구간 전체 삭제다. 그 밖의 `main/section/div` 골격, 표준 ID, 기본 코드와 순서를 바꾸지 않는다.
- CSS는 `assets/style.css`, JS는 `assets/app.js`의 붙여넣기 구간에 합친다. 기본 `io`와 이름이 겹치지 않게 하고, 블록별 고유 접두어로 전역 CSS·JS 충돌을 피한다.
- 리소스는 `assets/playbook`, `assets/scenariocanvas`, `assets/databook`으로 구분한다. 없는 블록의 불필요한 리소스는 넣지 않는다.
- 새 출력 에셋의 파일명·폴더명은 영어 소문자와 숫자로 작성한다. 확장자의 점과 템플릿의 정해진 이름·HTML 식별자는 예외다. 플러그인·스킬의 kebab-case 이름은 콘텐츠 에셋 규칙과 별개다.
- 경로는 ZIP 내부 상대 경로이며 실제 파일의 대소문자까지 일치해야 한다. HTML·JS의 URL 기준은 `index.html`, CSS `url()` 기준은 `assets/style.css`다.
- 최종 ZIP 루트에는 `index.html`과 `assets/`만 둔다. 가이드·검수 보고·캡처·플러그인 파일·썸네일은 업로드용 ZIP에 넣지 않는다. 썸네일은 플랫폼 별도 업로드용이다.
- 빌드 없이 정적 서버에서 실행되어야 하며 ZIP은 50MB 이하다. 이미지 단건 400KB는 권장치, 강제 한도로 취급하지 않는다. 과거 특정 콘텐츠의 용량 예외를 새 제작에 자동 적용하지 않는다.

## 구조와 식별자

| 순서 | main 직속 section id | data-screen-id | data-screen-name |
|---|---|---|---|
| 1 | playbook | playbook_main | {타이틀} 플레이북 |
| 2 | scenario-canvas | canvas_main | {타이틀} 시나리오 캔버스 |
| 3 선택 | data-book | databook_main | {타이틀} 데이터북 |

- 최상위 블록에는 `page-section`을 붙인다. `data-screen-id`는 템플릿 고정값 그대로 둔다.
- `data-screen-name`에서 `가족을 위한 두 번째 차`만 실제 타이틀로 바꾼다. 타이틀·블록명 사이 공백은 한 칸, 블록명은 고정이다. 새 구분 기호를 붙이지 않는다.
- 콘텐츠 제목을 받으면 출력 사본의 브라우저 탭 제목(`<head><title>`)도 그 제목 그대로 설정하고 HTML 특수문자를 이스케이프한다. `UserStory`, 폴더명, 블록명이나 이관 HTML의 원래 제목으로 대신하지 않는다. 이관 JS가 `document.title`을 덮어쓰는지도 확인한다. 새 제목을 받지 않은 단일 블록 수정은 기존 제목을 보존한다.
- 내부 추적 화면은 선택 사항이다. 만들면 `data-screen-id`와 읽기 쉬운 `data-screen-name`을 모두 둔다. ID는 `[a-z0-9_-]` 조합, 40자 이하, 문서 내 유일이다.
- 자식 추적 화면에 표준 ID나 `page-section`을 붙이지 않는다. 실제 서로 다른 세로 위치와 0이 아닌 높이를 차지하게 한다. 같은 의미의 기존 화면 ID는 유지한다.

## 스크롤과 금지 요소

- 기본 세로 스크롤로 모든 블록에 도달하도록 한다. 진입 효과는 템플릿의 IntersectionObserver를 유지한다.
- `html/body/main`의 스크롤 잠금, 최상위 블록 absolute/fixed 겹침, 전역 wheel/touch/keydown 페이지 전환, 이동 목적 preventDefault, 상태값으로 최상위 블록 교체를 금지한다.
- 클릭·가로 카드·스와이프·재생·내부 스크롤은 해당 컴포넌트 안에서만 처리한다. 페이지 이동과 참여 패널 입력을 가로채지 않는다.
- 카드 전환은 실제 scrollY를 읽기만 한다. 자동 스냅·강제 페이지 이동을 넣지 않는다. 영상 조작은 플레이북 내부에만 표시한다.
- 외부 하이퍼링크, 외부 iframe·CDN·스크립트·네트워크 호출·API·Firebase, localStorage/sessionStorage, Service Worker를 넣지 않는다.
- 자체 고정 헤더·메뉴·뒤로가기·진행 레일·참여 UI·인증·반응/공유 FAB·SDK·meta.json을 넣지 않는다. 플랫폼 예약 `.userstory-*`와 `/userstory-sdk/*`, 임의 History 변경도 금지한다.
- 금지 코드 제거에 따라 연출·픽셀이 달라지면 전후와 이유를 기록한다. 무관한 디자인 변경이나 원본 이미지 재작업은 하지 않는다.

## 화면과 플랫폼 UI

- 제작 기준 1920×1080 FHD 16:9, 최소 지원 1280×768이다. 모바일·태블릿 세로용 별도 화면은 만들지 않는다.
- 크기는 CSS viewport로 통일한다. DPR·screen.width로 크기를 바꾸지 않는다. 배경색은 원본과 대조한다.
- 이미지·영상·배경은 화면 중심을 기준으로 비율을 유지한다. 플랫폼 UI 회피를 이유로 전체 미디어를 좌우로 밀거나 비대칭 패딩·마진을 적용하지 않는다.
- 핵심 정보·별도 글·버튼·조작 요소만 상단 80px, 좌측 레일 40px, 좌상단 뒤로가기 80px, 하단 중앙 96px, 우상단 공유 FAB 96px, 우하단 약 340×420px을 피한다.
- 배경·장식 픽셀은 회피 영역까지 표시할 수 있다. 글이 합성된 이미지는 실제 글 영역의 가림 여부를 먼저 확인하고 필요한 이미지에만 개별 대응한다.
- 가이드 4장의 비대칭 CSS 예시는 핵심 요소 회피의 예시이지, 모든 미디어를 통째로 이동하는 의무가 아니다. 기본 템플릿 코드는 보존한다.

## 검수와 보고

- 제작 계획에는 코드 작성 후 [검수 태스크](tasks/audit.md)를 별도 단계로 넣는다. 가이드 7장·9장 전 항목을 1:1 대조한다.
- 기본 제작은 폴더 생성 → 제작 에이전트의 직접 화면·동작 검수 → 결과 보고까지다. `build`는 ZIP을 만들지 않는다. ZIP·납품용 포장을 요청받은 경우에만 검수 후 `package` 태스크를 별도로 수행한다.
- `scripts/userstory.py audit`는 코드·경로·ZIP의 정적 증거만 제공한다. 동적 URL·미디어 디코딩·실제 가림·내용 검수는 원문 대조와 실호스팅에서 확인한다. 정적 성공을 최종 합격으로 바꾸지 않는다.
- 제작한 폴더를 로컬 HTTP로 직접 열어 두 해상도로 섹션·연출별 캡처를 남기고 중심, 비율, 아티팩트, 겹침, 재생, 스크롤, 콘솔 오류·404를 확인한다. ZIP 포장 분리를 이유로 화면 검수를 생략하거나 사용자에게 전부 넘기지 않는다.
- 검수 캡처·상세 보고서는 OS 임시 경로의 작업별 폴더에 보관한다. 콘텐츠 출력·ZIP 옆이나 원본·플러그인 저장소에 `review` 등 별도 검수 폴더를 만들지 않는다. 사용자가 보관 위치를 지정하면 그 위치를 쓰되 업로드 ZIP 밖에 둔다.
- 임시 검수 자료를 기본 납품물로 나열하거나 자동으로 열지 않는다. 상세 보고서·캡처 경로는 요청 시 제공하되 검수 결과와 실패·미실행 항목은 항상 보고한다.
- 검수만 요청받으면 읽기 전용이다. 제작 후 실패 수정 또는 명시적인 수정 요청이 있을 때만 코드를 고친다. 원격 배포·Git 푸시·기존 납품본 덮어쓰기는 별도 요청 범위일 때만 한다.
- 정적 검사, 브라우저 검사, 플랫폼 게시 검증의 성공·실패·미실행을 분리한다. 브라우저/캡처 도구가 없으면 코드만으로 시각 합격을 선언하지 않는다.
- 최종 보고는 ① 콘텐츠 폴더(포장 요청 시 업로드용 ZIP) ② 변경 내용과 시각적 픽셀 변경 ③ 요청했으나 누락된 파일 ④ 사용자 브라우저 검수 필요 항목 순서다. ZIP을 만들지 않았다면 미포장으로 명시한다.
