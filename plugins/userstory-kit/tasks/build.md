# 제작 태스크

이 문서는 스킬에서 읽어 수행하는 작업 절차이며 예약 작업이나 자동 실행 서버가 아니다.

전체 흐름은 [00. 총괄](../skills/00-userstory/SKILL.md)이 맡고, 블록 절차는 [01. 플레이북](../skills/01-playbook/SKILL.md) → [02. 시나리오 캔버스](../skills/02-scenariocanvas/SKILL.md) → [03. 데이터북](../skills/03-databook/SKILL.md) 순서로 적용한다. 단일 블록 요청은 해당 블록만 작업하며 다른 블록의 입력을 새로 요구하지 않는다.

기존 콘텐츠의 블록 수정은 그 콘텐츠의 작업 사본에서 해당 슬롯·코드·리소스만 수정한다. 골격 없는 부품만 요청됐다면 본문·CSS·JS 조각만 준비한다. 아래 전체 페이지 `build` 명령으로 기존 다른 블록을 재생성하지 않는다. 최종 통합 검수·ZIP은 총괄의 책임이다.

## 입력 확인

| 입력 | 요구사항 |
|---|---|
| title | 실제 유저스토리 타이틀, 필수 |
| playbook | 사용자 HTML 또는 순수 영상·이미지, 필수. HTML은 연결된 CSS·JS·라이브러리·리소스를 포함한 폴더/ZIP까지 받는다 |
| scenariocanvas | 카드형 또는 세로형, 필수. 카드 순서와 원본 비율을 확인한다 |
| databook | 선택. 없으면 블록 삭제, 있으면 작성된 HTML 또는 로컬 PDF 등 실제 파일 확인 |
| output | 제작 출력 폴더와 ZIP 저장 위치. 원본·기존 납품본을 덮어쓸 필요가 있으면 정확한 대상을 먼저 확인한다 |

파일 목록과 실제 내용을 보고 블록을 분류한다. 단순히 파일명이 비슷하다는 이유로 콘텐츠를 추정하지 않는다. 타이틀·필수 리소스·카드 순서·블록 구분이 불명확하면 질문한다. 데이터북 부재는 정상 입력이다. 파일 제작이 불가능하면 시작 전에 보고한다.

## 작업 계획

다음 단계를 사용자에게 간단히 알리고 수행한다.

1. 가이드를 끝까지 읽고 입력 목록과 충돌 확인.
2. 기준 템플릿 사본 생성.
3. 플레이북 조립.
4. 시나리오 캔버스 조립.
5. 데이터북 조립 또는 ✂ 구간 전체 삭제.
6. 별도 검수 단계: `tasks/audit.md`의 코드·실호스팅·ZIP 검사.
7. 실패 항목 수정 및 해당 검수 재실행, ZIP 전달.

## 사본과 조립

- 플러그인 루트의 `assets/template/`를 출력으로 복사한다. 템플릿 원본이나 사용자 제공 원본을 직접 수정하지 않는다.
- Git은 빈 폴더를 저장하지 않으므로 사본에 `assets/playbook`, `assets/scenariocanvas`, `assets/databook`이 없으면 생성한다. 폴더 유지를 위한 숨김 파일은 콘텐츠에 넣지 않는다.
- 템플릿의 HTML·CSS·JS를 읽고 기본 코드와 표시 줄을 남긴다. HTML 변경 허용 범위는 붙여넣기 구간, 최상위 화면 이름의 타이틀 치환, 데이터북 삭제 구간뿐이다.
- 한 블록의 본문 → CSS/JS → 리소스 이동 → 경로 수정 → 참조 확인을 끝낸 뒤 다음 블록을 처리한다. 모든 블록에 무작정 전체 치환을 적용하지 않는다.
- 문서 통째로 중첩하지 말고 작업물의 body 본문만 해당 슬롯에 넣는다. style/script는 각 통합 파일의 슬롯에 넣는다.
- CSS는 블록 루트 아래로 범위를 제한하고 JS는 블록별 고유 이름 또는 지역 스코프를 사용한다. 템플릿의 `io`를 다시 선언하지 않는다.
- 새 에셋 이름은 `p1.webm`, `p1.webp`, `s1.webp`, `d1.pdf`, `f1.woff2`처럼 소문자·숫자로 짓고 해당 블록 폴더에 둔다. 원본→출력 이름 대응을 작업 기록에 남긴다.
- 이미 만들어진 연출·디자인·재생 조작을 우선 유지하되 가이드 금지 코드는 제거한다. 삭제·조정으로 달라진 화면은 변경 보고에 남긴다.

## 형식별 조립

작성된 HTML·CSS·JS가 있으면 원본 기능·연출을 유지하는 슬롯 조립을 우선한다. 플레이북 내부 형식은 고정하지 않으며, 영상/이미지 부품은 순수 미디어 입력의 기본값일 뿐이다. 양식 소스는 플러그인 안에 있으므로 예전 콘텐츠 저장소나 개발 PC 경로를 런타임에 찾지 않는다.

| 입력 | 부품 | 유지하는 방식 |
|---|---|---|
| 플레이북 html | [HTML 이관 태스크](playbookhtml.md)와 사용자 원본 코드 | DOM·디자인·게임·인터랙션·시퀀스·분기·기존 조작 유지. 영상/이미지 부품으로 대체하지 않음 |
| 플레이북 video | `assets/components/playbookvideo.html/css/js` | 포토 계열 시작 캡슐, 중앙 재생/정지·다시보기, 볼륨/음소거. 조작은 플레이북 안에만 표시, 종료 후 자동 스크롤 없음 |
| 플레이북 image | `assets/components/image.html/css` | 한 장당 img, 원본 비율, 제공 순서대로 세로 배치 |
| 시캔 card | `assets/components/canvascard.html/css/js` | 기존 Card 양식의 통일 크기·전환·우측 상단 회색 숫자 캡슐. 기본 scrollY로 넘기며 헤더·플레이북·자동 스냅 없음 |
| 시캔 vertical | `assets/components/image.html/css` | 기존 Journal의 중앙·원본 비율·자연 스크롤. 정적 한 장은 img 하나, SVG 인라인 로더·Lottie 없음 |

- 양식 HTML은 body 안에 넣는 조각이며 완성 페이지가 아니다. 시캔 조각에 다른 블록이나 main/section을 다시 넣지 않는다.
- 이미지형·세로형은 공통 이미지 부품을 한 번만 사용한다. 동일 CSS/JS를 두 번 붙이거나 이름만 다른 양식을 만들지 않는다.
- 카드 크기는 CSS viewport로 계산한다. DPR·screen.width로 분기하지 않는다. 카드 원본 비율은 object-fit: contain으로 보존한다.
- 영상·이미지를 임의 교체하거나 원본을 손실 압축하지 않는다. 작성된 영상 시퀀스·게임/분기·SVG 애니메이션은 단순 영상/이미지 양식으로 바꾸지 말고 필요한 원본 코드를 슬롯에 조립한다.
- 모든 이미지에는 의미 있는 alt를 둔다. 이미지 합성 글의 가림 여부를 먼저 확인한다. 전체 미디어를 비대칭으로 이동시키지 않는다.
- 데이터북이 있으면 로컬 파일·작성된 본문을 조립한다. PDF만 제공됐을 때 외부 뷰어를 호출하지 않는다. 복잡한 전용 뷰어를 별도 요구 없이 만들지 않는다.
- 데이터북이 없으면 ✂ 시작·끝 표시와 그 사이 section 전체를 삭제한다. 빈 블록이나 가짜 데이터북을 남기지 않는다.

## 순수 미디어 조립 실행

Python 3.10+ 표준 라이브러리만 사용한다. 실행기부터 확인하고, 없으면 임의 설치하지 말고 파일 도구로 같은 슬롯 조립을 수행한다. 플러그인 루트는 이 문서의 상위 폴더다.

플러그인 밖에 입력 JSON을 만든다. 경로는 JSON 파일 위치 기준이며 절대 경로도 가능하다. 파일 순서는 배열 순서다.

```json
{
  "title": "가족을 위한 두 번째 차",
  "playbook": {"type": "video", "files": [{"path": "input/opening.webm", "alt": "가족의 두 번째 차를 고민하는 이야기"}]},
  "scenariocanvas": {"type": "card", "files": ["input/card1.webp", "input/card2.webp"], "background": "#e8e7e4"},
  "databook": null
}
```

`files`는 파일 경로 또는 `{path, alt}` 배열이다. 선택 `background`는 6자리 HEX이며 원본 바탕색과 대조한다. 영상은 완성 영상 한 파일, 카드·세로형·이미지는 한 장 이상이다. 선택 데이터북의 이미지 입력은 `{"type":"image","files":["input/data.svg"]}`다. 이 CLI는 순수 미디어 전용이며 `type: html`을 받지 않는다. 사용자 플레이북 HTML·게임·영상 분기는 [HTML 이관 태스크](playbookhtml.md)로 처리하고, PDF 등은 해당 블록의 슬롯 조립 절차로 처리한다. 누락 파일을 버리고 자동 생성으로 채우지 않는다.

```text
python <플러그인 루트>/scripts/userstory.py build <입력.json> <새 출력 폴더> <출력 폴더 밖 ZIP>
python <플러그인 루트>/scripts/userstory.py audit <출력 폴더> --title "실제 타이틀"
node --check <출력 폴더>/assets/app.js
python <플러그인 루트>/scripts/userstory.py audit <ZIP> --title "실제 타이틀"
```

조립기는 원본을 복사하고 `p1/s1/d1` 등으로 리디렉터링한다. 기존 출력 폴더·ZIP 덮어쓰기를 거부하고 플러그인 안에 결과를 쓰지 않는다. 표준 골격·기본 코드 보존, 식별자, 상대 경로·대소문자, SVG XML/참조, 빈 파일, 금지 코드 후보와 ZIP CRC/용량을 검사한다. 파일 대응은 JSON 결과로 보고한다. 실패 시 산출물은 검사·수리용으로 남으며 완료가 아니다.

양식 수정 뒤에는 `python <플러그인 루트>/scripts/test_userstory.py`로 4가지 형식 조합 × 데이터북 유/무와 거부 조건을 확인한다. 테스트의 영상은 경로 검사 전용이며 재생 성공 증거가 아니다.

## 검수·납품

[검수 태스크](audit.md)를 수행한다. 코드만 통과했다고 최종 합격을 선언하지 않는다. 두 해상도 캡처와 검수 결과는 업로드 ZIP 밖에 둔다.

최종 ZIP에는 `index.html`과 `assets/`만 담고 다시 열어 상대 경로·대소문자·용량을 확인한다. ZIP을 만들 수 있어도 필수 파일 또는 시각 검수가 빠졌으면 검수용 산출물로 표시하며 미완료 항목을 함께 보고한다.

최종 보고 양식:

1. ZIP: 실제 파일 링크, 용량, 검수용/납품 가능 여부.
2. 변경: 파일 구조·경로·제거한 금지 코드와 시각적으로 달라진 픽셀/위치/연출. 없으면 없음.
3. 누락: 요청된 파일 중 제공되지 않아 반영 못한 파일. 없으면 없음.
4. 사용자 검수: 미실행 또는 실제 플랫폼에서만 확인 가능한 항목. 코드/실호스팅 검사의 성공·실패·미실행도 명시.
