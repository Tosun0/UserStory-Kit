# ZIP 포장 태스크

ZIP·납품용 포장을 요청받았을 때만 수행한다. 기본 제작은 콘텐츠 폴더와 직접 검수 결과 보고까지이며 ZIP을 자동 생성하지 않는다. 별도 스킬이나 예약 작업이 아니라 [00. 총괄](../skills/00-userstory/SKILL.md)이 수행하는 후속 절차다.

## 포장 전 확인

- 완성 콘텐츠 폴더, 실제 제목, 출력 ZIP 위치를 확인한다. 새 제작이나 블록 재조립을 하지 않는다.
- [검수 태스크](audit.md)의 코드·내용·직접 실호스팅 화면 검수 결과를 확인한다. 기록이 없거나 콘텐츠가 변경됐으면 필요한 검수를 먼저 수행한다. ZIP이 생성됐다는 이유로 화면 검수를 통과 처리하지 않는다.
- 필수 파일 누락·검수 실패·필수 검수 미실행이 남으면 보고하고 납품용 포장을 진행하지 않는다. 사용자가 검수용 ZIP을 명시적으로 요청하면 미완료 항목을 함께 표시해 포장할 수 있다.
- 검수 자료는 공통 지침의 임시 경로에 보관한다. 콘텐츠나 ZIP 옆에 리뷰 폴더를 새로 만들지 않는다.

## 포장과 재검사

Python 3.10+ 표준 라이브러리를 사용한다. 플러그인 밖 콘텐츠 폴더와 그 폴더 밖 새 ZIP 경로를 지정한다. 실행기가 없으면 동일 구조로 파일 도구를 사용한다.

```text
python <플러그인 루트>/scripts/userstory.py package <완성 콘텐츠 폴더> <출력 ZIP> --title "실제 타이틀"
python <플러그인 루트>/scripts/userstory.py audit <출력 ZIP> --title "실제 타이틀"
```

- `package`는 기존 폴더를 정적으로 재검사한 뒤 원본 바이트를 그대로 포장한다. 기존 ZIP 덮어쓰기, 플러그인 내부 출력, 콘텐츠 폴더 내부 ZIP 생성을 거부한다. 콘텐츠를 수정하거나 미디어를 재압축하지 않는다.
- ZIP 루트에는 `index.html`과 `assets/`만 담는다. 폴더 한 겹을 추가하지 않는다. 원본·검수 보고·캡처·플러그인 파일은 넣지 않는다.
- 실제 ZIP 엔트리의 이름·상대 경로·대소문자·참조 파일·CRC·총 용량 50MB 이하를 재검사한다. 가이드 7장·9장의 미포장 항목을 이 단계에서 완료한다.
- 정적 결과의 `browser/media_decode/platform: not_run`은 화면 검수 증거가 아니다. 직접 확인한 기록과 구분해서 보고한다. 포장 후 실패한 ZIP은 수리용이며 납품 완료가 아니다.

최종 보고는 ① ZIP 링크·용량·검수용/납품 가능 여부 ② 변경 내용 ③ 누락 파일 ④ 미실행·사용자 확인 항목 순서다. 포장만 했다면 콘텐츠 변경은 없음으로 명시한다.
