# 검수 태스크

검수 대상은 제작된 폴더와 최종 ZIP이다. 빈 기준 템플릿 검증을 실제 콘텐츠 합격으로 대체하지 않는다. 검수만 요청받으면 읽기 전용으로 보고한다. 제작 후 검수 또는 수정 요청인 경우 실패 항목을 수정하고 관련 검증을 다시 한다.

[00. 총괄](../skills/00-userstory/SKILL.md)이 전체 체크리스트와 최종 결과를 맡는다. 01~03 블록 스킬은 변경한 블록의 근거와 미실행 항목을 넘기며 이 체크리스트를 단일 블록 합격으로 축소하지 않는다.

## 2. 코드·파일 무결성 검사

- `python <플러그인 루트>/scripts/userstory.py audit <폴더 또는 ZIP> --title "실제 타이틀"`을 실행한다. 파일·기본 골격·식별자·경로·금지 코드 후보·SVG·ZIP CRC/용량의 정적 증거를 제공한다. `browser/media_decode/platform: not_run`과 `delivery: review`를 최종 통과로 바꾸지 않는다.
- 임의 JS의 동적 URL, 실제 미디어 디코딩, CSS의 모든 실행 조건, 금칙어·이미지 합성 글은 정적 도구만으로 판정할 수 없다. 아래 소스 대조와 실호스팅 검사를 함께 수행한다. 검사기 자체의 256MB ZIP 해제 용량 제한은 가이드 한도가 아니며, 그 제한에 걸리면 원본 폴더로 검수한다.
- HTML DOM으로 main 직속 블록의 순서·class·표준 ID·고정 screen ID·실제 타이틀을 확인한다. `<head><title>`이 한 번만 존재하고 디코딩한 텍스트가 요청 제목과 일치하는지, 문서 전체 id와 screen ID 중복도 확인한다.
- 기준 템플릿과 비교하여 슬롯 밖 무단 변경이 없는지 확인한다. `<title>` 텍스트·최상위 화면 이름의 타이틀 치환과 데이터북 삭제는 허용한다. CSS/JS 기본 코드도 비교한다.
- 모든 소스 파일에서 외부 하이퍼링크, 외부 iframe·스크립트·CSS·폰트·이미지·API 요청, 스토리지, Service Worker, 예약 class/경로, 고정 헤더/메뉴, 자체 플랫폼 UI, History 변경을 검사한다. 단순 문자열 일치와 실제 실행·참조를 구분한다.
- html/body/main의 overflow 잠금·고정 높이·겹친 최상위 블록, 전역 wheel/touch/keydown·페이지 이동 preventDefault·블록 show/hide를 검사한다. 컴포넌트 이벤트와 전역 페이지 이동을 구분한다.
- HTML src/href/srcset/poster/data, CSS url()/import, JS의 리소스 경로를 추적한다. 동적으로 합성하는 URL도 실제 생성 결과를 확인한다.
- URL의 query/hash는 파일 확인 시 분리하되 경로의 대소문자는 그대로 비교한다. percent-encoding은 URL 의미에 맞게 해석한다. CSS URL은 CSS 파일 기준, HTML·app.js URL은 index.html 기준이다.
- 절대 URL·루트 절대 경로·ZIP 외부 경로를 차단하고 폴더 밖으로 탈출하는 상대 경로를 검사한다. SVG의 표준 XML namespace URI 같은 비요청 메타데이터를 외부 호출로 오판하지 않는다.
- 이미지·영상·폰트·라이브러리 등 참조 파일이 ZIP 안에 실제로 있고 읽을 수 있는지 확인한다. 필수 리소스 누락, 대소문자 불일치, 손상·빈 파일은 실패다.
- JS 구문 검사를 수행한다. `node --check` 통과는 런타임·영상 재생 성공의 증거가 아니다.
- ZIP을 만든 뒤 ZIP 엔트리 자체로 루트 구조·이름·용량·파일 무결성을 재확인한다. 사용자 소스를 지우거나 원본을 손실 압축하지 않는다.

## 3. 실호스팅 화면 검수

- 제작 결과를 로컬 HTTP 정적 서버로 호스팅한다. file:// 또는 코드 수치만으로 실호스팅 검사에 갈음하지 않는다. 검수용 로컬 서버는 원격 게시가 아니다.
- 브라우저 viewport를 각각 1920×1080, 1280×768로 설정하고 100% 배율과 실제 viewport 값을 기록한다. 임의의 DPR을 맞추기 위해 원본 픽셀을 재가공하지 않는다.
- 초기화와 블록 인터랙션 뒤에도 `document.title`이 요청 제목과 일치하고 브라우저 탭에 표시되는지 확인한다.
- 플레이북의 시작·재생/정지·종료·다시보기 등 존재하는 연출, 카드의 각 장/전환, 세로형의 시작·중간·끝, 데이터북이 있다면 각 화면을 검수한다. 없는 기능을 검수용으로 추가하지 않는다.
- 해상도별·섹션별·연출별 캡처를 ZIP 밖에 저장한다. 이미지·영상·배경의 화면 중심, 종횡비, 잘림, 아티팩트, 의도하지 않은 겹침을 확인한다.
- 플랫폼 회피 영역과 실제 핵심 글/버튼 경계를 대조한다. 배경/장식 픽셀은 허용한다. 합성 글의 실제 가림을 확인하지 않고 전체 이미지를 옮기지 않는다. 좌상단 80px 및 우상단 공유 FAB 96px도 점검한다.
- 휠·트랙패드·Page Down으로 끝까지 이동, 실제 scrollY 변화, 첫/마지막 블록에 갇히지 않음, 내부 인터랙션 후 다음 블록 접근, 콘솔 오류·asset 404·외부 요청 0건을 확인한다.
- 사용할 수 있는 브라우저 도구가 없거나 실제 트랙패드/플랫폼 UI를 검사할 수 없으면 해당 항목을 미실행으로 남겨 사용자 확인 항목에 넣는다. 자동 검사 성공을 사람의 검수 성공으로 바꾸지 않는다.

## 4. 수정과 결과

실패 항목을 수정할 권한이 있으면 원인을 수정하고 관련 검사·캡처·ZIP 재검사를 반복한다. 큰 디자인 변경이나 가이드 의도 충돌은 먼저 질문한다. 최종 ZIP은 모든 필수 검사 통과 시 납품 가능, 누락·미실행이 남으면 검수용으로 표시한다.

가이드 대조 결과와 함께 코드·파일 검사, 실호스팅 화면 검사, 실제 플랫폼 게시 검증을 각각 성공/실패/미실행으로 보고한다. 시각 변경은 해당 섹션·요소, 전후 위치/색/크기/연출과 이유로 설명하고 캡처 경로를 붙인다.
