# 01_플레이북

플러그인 루트는 이 디렉터리의 `../..`다. [공통 지침](../../AGENTS.md)과 [원본 가이드](../../references/guidev0929.md)를 읽고 적용한다. 동일 작업에서 읽은 자료는 이어 사용한다.

플레이북의 내부 구조는 고정 양식이 아니다. 제공된 HTML이 있으면 그 작업물을 우선하며, 내부에 영상·이미지가 있어도 순수 미디어 양식으로 대체하지 않는다.

1. 현재 플레이북 코드와 입력을 사용자 HTML / 순수 영상 / 순수 이미지로 구분하고 원본 기능·제공 순서·의존 파일을 확인한다. [제작 태스크](../../tasks/build.md)의 사본·슬롯 조립 규칙을 적용한다.
2. 사용자 HTML은 [HTML 이관 태스크](../../tasks/playbookhtml.md)를 읽고 본문·CSS·JS·로컬 의존 리소스를 이관한다. 순수 영상 한 파일에만 [playbookvideo](../../assets/components/playbookvideo.html)의 HTML·CSS·JS를, 순수 이미지에만 [공통 img](../../assets/components/image.html)의 HTML·CSS를 사용한다. 한 장짜리는 img 하나, 여러 장은 지정된 순서다.
3. 리소스는 `assets/playbook`에 복사하고 실제 파일명과 대소문자까지 맞춰 리디렉터링한다. HTML은 플레이북 붙여넣기 구간, CSS/JS는 통합 파일의 해당 블록 코드만 작업한다. 시캔·데이터북과 공유 코드의 기존 사용처를 보존한다.
4. 순수 영상 양식은 중앙·원본 비율과 시작·재생/정지·볼륨/음소거·종료·중앙 다시보기를 확인한다. 사용자 HTML은 원래 존재하는 조작·게임·분기·재시작을 검증하며, 없는 재생 UI를 임의로 붙이지 않는다. 이벤트는 블록 안에 한정하고 자동 페이지 이동이나 전역 입력 가로채기를 넣지 않는다.
5. 변경한 블록의 경로·식별자·JS 구문과 두 해상도 화면·동작을 [검수 기준](../../tasks/audit.md)으로 확인한다. 검수만 요청받으면 읽기 전용이며 미실행 항목은 그대로 보고한다.

전체 `userstory.py build`를 플레이북 수정용으로 실행해 다른 블록을 재생성하지 않는다. 변경 코드·리소스·픽셀 차이·검증 결과를 [00_총괄](../00-userstory/SKILL.md)의 최종 검수에 넘긴다. 단일 블록 검사로 전체 콘텐츠 합격을 선언하지 않는다.
