# 00_총괄

이 스킬 디렉터리의 `../..`가 플러그인 루트다. 개발 PC의 고정 경로를 사용하지 않는다.

1. [공통 지침](../../AGENTS.md), [원본 가이드](../../references/guidev0929.md), [기준 템플릿](../../assets/template/index.html)과 그 옆 `assets/style.css`·`assets/app.js`를 읽고 요청과 대조한다. 동일 작업에서 읽은 자료는 이어 사용한다.
2. 제목, 플레이북의 사용자 HTML/순수 영상/순수 이미지 구분, 시캔의 카드/세로형 구분과 순서, 데이터북 유무, 출력 위치를 확인한다. 필수 파일 누락이나 블록 구분이 모호하면 필요한 사항만 질문한다. 없는 데이터북과 제공되지 않은 필수 파일을 혼동하지 않는다.
3. [제작 태스크](../../tasks/build.md)에 따라 하나의 출력 사본에서 아래 블록 절차를 순서대로 적용한다.
   - [01_플레이북](../01-playbook/SKILL.md): 사용자 HTML 이관 또는 순수 영상·이미지 플레이북 조립.
   - [02_시나리오 캔버스](../02-scenariocanvas/SKILL.md): 카드 또는 세로형 시캔.
   - [03_데이터북](../03-databook/SKILL.md): 선택 데이터북 조립 또는 전체 블록 삭제.
4. 순수 미디어 조합은 [조립기](../../scripts/userstory.py)의 `build`를 한 번 실행한다. 블록마다 전체 페이지를 새로 빌드하지 않는다. 작성된 HTML·게임·영상 분기·PDF는 각 블록 절차에 따라 원본 기능을 유지하는 슬롯 조립으로 처리한다.
5. [검수 태스크](../../tasks/audit.md)의 가이드 7장·9장 전 항목을 대조하고, 정적 검사와 두 해상도 실호스팅·플랫폼 검증의 성공/실패/미실행을 구분한다. 실패 수정 권한이 있을 때만 수정 후 재검사한다.
6. ZIP 루트·경로·대소문자·용량을 재확인하고, ZIP·변경 및 시각적 차이·누락 파일·사용자 확인 항목을 보고한다. 미실행 검수가 남으면 납품 합격으로 선언하지 않는다.

전체 검수만 요청받으면 3~4단계 제작과 ZIP 재생성을 하지 않고 기존 폴더/ZIP을 읽기 전용으로 검사한다. 등록·구상 요청을 콘텐츠 제작이나 원격 배포로 확대하지 않는다.
