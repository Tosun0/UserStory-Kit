# 00. 총괄

이 스킬 디렉터리의 `../..`가 플러그인 루트다. 개발 PC의 고정 경로를 사용하지 않는다.

1. [공통 지침](../../AGENTS.md), [원본 가이드](../../references/guidev0929.md), [기준 템플릿](../../assets/template/index.html)과 그 옆 `assets/style.css`·`assets/app.js`를 읽고 요청과 대조한다. 동일 작업에서 읽은 자료는 이어 사용한다.
2. 제목, 플레이북의 사용자 HTML/순수 영상/순수 이미지 구분, 시캔의 카드/세로형 구분과 순서, 데이터북 유무, 출력 위치를 확인한다. 받은 콘텐츠 제목을 브라우저 탭의 `<title>`과 최상위 화면 이름에 함께 반영한다. 필수 파일 누락이나 블록 구분이 모호하면 필요한 사항만 질문한다. 없는 데이터북과 제공되지 않은 필수 파일을 혼동하지 않는다.
3. [제작 태스크](../../tasks/build.md)에 따라 하나의 출력 사본에서 아래 블록 절차를 순서대로 적용한다.
   - [01. 플레이북](../01-playbook/SKILL.md): 사용자 HTML 이관 또는 순수 영상·이미지 플레이북 조립.
   - [02. 시나리오 캔버스](../02-scenariocanvas/SKILL.md): 카드 또는 세로형 시캔.
   - [03. 데이터북](../03-databook/SKILL.md): 선택 데이터북 조립 또는 전체 블록 삭제.
4. 순수 미디어 조합은 [조립기](../../scripts/userstory.py)의 `build`를 한 번 실행해 콘텐츠 폴더만 만든다. 블록마다 전체 페이지를 새로 빌드하지 않는다. 작성된 HTML·게임·영상 분기·PDF는 각 블록 절차에 따라 원본 기능을 유지하는 슬롯 조립으로 처리한다.
5. [검수 태스크](../../tasks/audit.md)의 가이드 7장·9장 전 항목을 대조하고, 제작 결과를 로컬 HTTP로 직접 열어 두 해상도로 화면·동작을 확인한다. 정적 검사·실호스팅·플랫폼 검증의 성공/실패/미실행을 구분한다. 실패 수정 권한이 있을 때만 수정 후 재검사한다.
6. 기본 제작은 콘텐츠 폴더·변경 및 시각적 차이·누락 파일·검수 결과를 보고하고 끝낸다. ZIP·납품용 포장을 요청받은 경우에만 [ZIP 포장 태스크](../../tasks/package.md)를 별도로 수행한다. 검수 자료는 공통 지침의 임시 경로에 보관하며 별도 납품물로 나열하지 않는다. 미포장·미실행을 납품 합격으로 선언하지 않는다.

전체 검수만 요청받으면 3~4단계 제작과 ZIP 재생성을 하지 않고 기존 폴더/ZIP을 읽기 전용으로 검사한다. 등록·구상 요청을 콘텐츠 제작이나 원격 배포로 확대하지 않는다.
